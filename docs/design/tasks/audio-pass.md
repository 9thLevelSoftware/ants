## Work
1. **Loudness (ruling §K).** Add an integrated-loudness estimator for offline renders (ITU-R BS.1770 K-weighting: the two-stage pre-filter, 400 ms blocks, absolute gate at -70 LUFS and relative gate at -10 LU; a pure function over Float32Array with unit tests against synthetic signals: a 997 Hz sine at -23 dBFS reads -23.0 ± 0.3 LUFS). Then retune so that offline renders of these scenes meet the targets: calm surface day (garden, clear, noon, no events) -27 ± 2 LUFS; calm underground (brood chamber) -30 ± 3; rain (downpour, surface) -22 ± 2; a human event at its peak (footstep impact beside the listener) -14 ± 3 with true peak ≤ -1 dBFS; night surface -30 ± 3. Quiet foley of the possessed ant (step, pick-up, dig bite) must be audible over the calm bed: its short-term level within 8 LU of the bed. Do it with a master trim and per-bus levels in `tuning.ts`, plus a gentle compressor on the giants bus (so the thud does not force everything else down); keep the limiter. Record before/after numbers in the README.
2. **Stage 2 cues.** Build a table test that fails for any event kind in the simulation's event unions that the audio system neither maps nor lists as deliberately silent. Then map them: creatures (per family: approach taps, strike, bird wing whoosh / landing thud / pecks, antlion spray, fly buzz), combat (bite, grapple, acid spray, death), rivals (first contact, raid), weather (rain onset/intensity following the weather read-out, raindrop hits near the listener as discrete heavy impacts at ant scale, thunder delayed by distance after the lightning flash, wind gusts, puddle/flood gurgle, collapse rumble), human events (every event type and phase with the long attenuation distances), founding (dig, seal tamp, first egg, first worker eclosion, hand-over), progression milestones, photo capture (shutter click through the UI facade when photo mode reports a capture; if it has no hook, list it).
3. **Known defects from the README and the integrator.** Bite strength: every bite crunches because the sim emits strength 1 — decide from data the adapter can read (target kind/hardness) until the runner passes it. Duplicate dig-bite cue (runner and `nest/bite.ts` both emit): de-duplicate on the audio side by (tick, ant, cue). Alarm shimmer follows its setting.
4. **Settings > Audio.** A status line that tells the truth (running / waiting for a click / blocked by the browser / not supported / muted while hidden) with a "Click to enable sound" button when a gesture is needed, using `audioStatus` / `audioEnable` from `@/audio`. Volume sliders take effect immediately; a "Test" button per bus plays a representative sound.
5. **Debug + diagnostics.** `window.__foundressAudio` already exists; keep it and make sure `status()`, `cueLog()` and a new `loudness()` (short-term LUFS of the analyser tap) work in the real game. Report what `__game` aliases would be useful instead of editing the debug API yourself.
6. **Packaging.** `INCLUDE_ALL_AUDIO` is false and files ship by reference scan: prove every file id the cue table and ambience matrix can ask for is in the scan result (a test that fails on a missing or an unused shipped audio file), then build `npm run build:portable` once and confirm audio decodes there (offline render inside the classic build page).
7. **Cost.** 32 voices + ambience under 1 ms main-thread time per frame (measure in the demo page; report the number and the machine load at the time).

## Acceptance criteria
1. Typecheck clean; `npx vitest run src/audio` green including the new loudness, coverage-table and packaging tests.
2. `spikes/audio-demo` renders each target scene offline and prints LUFS, true peak and band energy; the numbers meet work item 1 (table in your report, before and after).
3. In the real game through the harness (`?test=1` normally silences audio; use the documented override) a 60 s scripted run with rain, a footstep event, digging and a bird logs the expected cues in `cueLog()` with no console errors.
4. Audio still never starts before a user gesture; refusal leaves the game playable and the status line says why.
5. Works in the classic single-file build.
